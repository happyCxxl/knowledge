# 跨前后端的口径检查

放不属于单一侧（后端 / 前端）的检查脚本。当前一个：注释口径。

## check-comments.mjs

注释只写"做什么"（职责与行为），不写"谁写的 / 为什么 / 从哪来 / 阶段 X"。规范两处各有一份同义条款：
`web/docs/前端开发规范.md` §9.1（前端）与 `tools/backend/README.md` 交付自查清单（后端）。本脚本是这条规范的机器执行者。

```
node tools/check-comments.mjs             # 全量：命中 ERROR 退出 1
node tools/check-comments.mjs --strings    # 额外报告字符串字面量里的阶段词（只读，不判失败）
```

覆盖范围：`knowledge-*/src`、`web/src`、`web/docs`、`docs`、`tools`、根 `README.md` 与 `.husky/pre-commit`、`.husky/pre-push`。

判定分两级：

| 级别  | 内容                                                                                                                       | 结果               |
|-------|----------------------------------------------------------------------------------------------------------------------------|--------------------|
| ERROR | 阶段词、沿革词、因果与目的词、"给谁用"表述（完整清单见脚本顶部的 `ERROR_WORDS`；口径豁免：本行即禁词表本身，故不逐词列出） | 退出 1，推送被拦   |
| WARN  | `调用方` / `调用侧` / `调用点`、`否则`、`为了`、`留给`、`故意`（口径豁免：本行即词表本身）                                 | 只列清单，逐条判断 |

两条边界：

- **只扫注释文本与文档正文，不扫字符串字面量**。用户可见文案（错误码消息、界面文字）改不改由评审定，`--strings` 提供只读清单；
- **领域时间语义不算沿革**（如"该账号此前签发的令牌全部失效"），脚本内置白名单跳过。

某行确实需要保留禁词时，在该行写 `口径豁免：<理由>`，脚本跳过该行。

接入点：`.husky/pre-push` 的第 1 步（改动涉及 `.java/.ts/.vue/.css/.mjs/.md/.husky/` 时执行）。`mvn -o verify` 与 `pnpm lint` 不重复这份词表——避免同一份规则两处维护。
