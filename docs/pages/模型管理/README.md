# 模型管理

模型能力平台的**管理页**（仅管理员）：维护「哪些模型可用、它的能力、价格与限额」，发起一次连通性测试，并只读查看调用用量与成本。页面分两个二级视图：**模型清单**（主入口，行内可编辑 / 试连 / 启停，右上「新增模型」）与**用量与成本**（概览卡 + 调用明细表）。

口径的三条前提（见 `../../design/模型能力平台-方案设计.md` 的 §4.1 / §4.2 / §8）：

- **厂商连接与密钥都在配置**（`knowledge.model.vendors.<厂商码>`），库里只有一张 `kb_model` 表、只存厂商码；**页面没有密钥与地址的任何入口**，厂商下拉的选项来自配置、不可新建。
- **限额只写在模型行上**（没有厂商级限额）；价格四列按能力对应（每百万 token / 按页 / 按千次），都能留空。
- **路由参数在配置里**（`knowledge.model.route.*`），页面不做策略、不做灰度、不做人工优先级。

## 厂商下拉与密钥口径

厂商下拉的选项**只能来自配置**：`GET /admin/model/vendors` 返回配置里列出的厂商码、展示名、**是否已配密钥**（布尔）与是否唯一厂商。密钥内容没有任何下发路径 —— 接口返回体里既没有密钥取值，也没有密钥字段（只读清单的 VO 只有 `code` / `displayName` / `credentialConfigured` / `soleVendor` 四项）；轮换密钥与改地址走配置 + 重启。

保存模型时**厂商码必须出现在配置里**：不在配置里回 `40461`（`MODEL_VENDOR_UNKNOWN`），消息带配置键 `knowledge.model.vendors` 与当前已配置的厂商清单，避免"配错到运行期才发现"。

厂商的展示名配置里没有这一项，服务端按厂商码给内置映射（`dashscope` → 阿里百炼、`self-ocr` → 自建推理、`openai` → OpenAI），未命中回落厂商码本身。

## 试连（连通性测试）

试连**发一次最小真实请求**：按模型声明的能力选一组 —— 声明 `CHAT` 走对话、声明 `EMBEDDING` 走向量、只声明视觉三能力（`TABLE_STRUCTURE` / `OCR` / `LAYOUT`）时走视觉。视觉入参的图像取一枚内置的 1×1 PNG 常量（页面与解析侧都还没有图像字节来源，见待办 `MODEL-14`）。测试与启用状态无关：停用的模型也能试连。

结论**无论成败都写回** `kb_model` 的 `probe_at` / `probe_result`；失败不改 HTTP 语义，错误码与可读消息在返回体的 `errorCode` / `message` 里，页面据它弹提示并刷新清单。试连是一次真实调用，会在 `kb_model_call_log` 落一行明细。

## 两处口径差异（如实登记，不自行改口径）

- **能力字典**：方案 §4.6 的字典含 `RERANK` / `IMAGE`，`knowledge-common` 的 `ModelCapability` 枚举只有 `CHAT` / `EMBEDDING` / `OCR` / `LAYOUT` / `TABLE_STRUCTURE` 五项。接口按枚举校验，页面也按五项给选项，**这两个取值当前会被拒**（差异登记见 `../../design/模型能力平台-待办清单.md` 第六节第 5 项）。
- **明细的业务归属列**：`bizType` / `bizId` / `traceId` 当前写空（§4.5 v22 口径），明细表的「业务」列读作 `—`。

## 待定项

- **厂商展示名没有配置来源**：配置项里只有 `base-url` / `auth-type` / `api-key` / `timeout-ms` / `max-retries` 五项，展示名取服务端内置映射，接入新厂商时新码值的展示名会回落成码值本身；是否给配置加一个展示名键尚未决定。
- **编辑时允许改厂商码**：厂商码与模型名共同构成唯一键，改成另一家等于换一条模型行；当前实现允许改（下拉仍只列配置里的厂商），是否改为编辑时锁定厂商码尚未决定。
- **试连的视觉入参依赖内置图像常量**：图像字节的正式来源（页面或区域栅格化、对象存储键约定）登记在 `MODEL-14`，接通之前视觉模型的试连结论只代表"该端点能接受一枚 1×1 PNG"。
- **试连会落一行调用明细**：用量视图的「调用总数」包含试连次数；是否给试连加一个不落明细的标记尚未决定。
- **切换次数按前 500 条明细统计**：概览接口没有按 `route_reason` 的分组计数，页面用明细接口（`limit` 500）在本地统计，超过 500 条时这个数字只是"最近一批"的口径；是否给概览补一个分组字段尚未决定。
- **生效区间在抽屉里**：§8.2 的抽屉字段清单没有列生效区间，接口收参里有这两段；不给入口会在每次编辑时把既有区间覆盖成空，于是抽屉补了两个时间选择器，是否保留需要与页面口径一起定。
