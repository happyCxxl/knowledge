# 接口逻辑

本文件写「后端拿到请求之后到底做了什么」。入口是 `ModelAdminController`（模型与厂商六条）与 `ModelUsageController`（用量两条），模型侧的编排与校验全在 `ModelAdminServiceImpl`，库表读写走 `KbModelDbService`（表 `kb_model`），试连的真实调用走 `knowledge-model` 的 `ModelInvoker`。通用机制（错误码分段、鉴权、公共字段填充、逻辑删除）见 `../../README.md` 的「全局约定」章。

## 一、清单

`GET /admin/model/models`（`ModelAdminServiceImpl.list`）：

1. **收参解析**：`capability` 按 `ModelCapability.of` 解析（留空即不过滤，填了不在字典内回 `40001`）；`status` 按 `ENABLED` / `DISABLED` 字典解析（大小写不敏感，落库取大写，留空即不过滤）；`keyword` 去首尾空白，空白即不传。
2. **取数**：`KbModelDbService.listByCondition(status, keyword)` —— 状态与关键字**下推到 SQL**（关键字在 `model_key` 与 `display_name` 两列上做 `OR` 模糊匹配），排序是 `vendor_code` 升序、`model_key` 升序；`del_flag = '0'` 由 `@TableLogic` 自动补上。
3. **能力过滤在应用侧**：能力是多值逗号分隔串，候选行取回后按 `ModelCapability.parse` 切分比对。**不用 `LIKE`** 的理由与目录端口一致：子串会误命中（`OCR` 会串到别的短取值上），而 `kb_model` 是配置级表、行数在几十行量级，整表读进内存没有规模风险。这一处口径与 `DbModelCatalog.listByCapability` 同源。
4. **字段映射**：逐行转 `ModelItemVO`，能力串切成字典名清单，厂商展示名按内置映射补齐。

清单**不分页**：接口返回数组，页面按条数展示；`/models` 也不接受 `current` / `size` 这类参数。

## 二、新增与编辑

`POST /admin/model/models` 与 `PUT /admin/model/models/{id}` 走同一段校验与赋值（`fill`），编辑额外做两件事：先按主键取行（取不到回 `40464`），唯一键判定排除本行。

**校验顺序**（任一条不通过即抛出，后面的步骤不再执行）：

| 序 | 校验                                                                        | 不通过的错误码与消息口径                                                                                      |
|----|-----------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------|
| 1  | 请求体非空                                                                  | `40001`「请求体不能为空」                                                                                     |
| 2  | 厂商码非空且不超过 64 字符                                                  | `40001`「厂商码不能为空」/「厂商码最长 64 字符，当前 N」                                                      |
| 3  | **厂商码必须出现在 `knowledge.model.vendors` 里**                           | `40461`「厂商码不在配置里：<码>（配置键 knowledge.model.vendors，已配置厂商：[…]）」                          |
| 4  | 模型名非空且不超过 128 字符                                                 | `40001`「模型名不能为空」/「模型名最长 128 字符，当前 N」                                                     |
| 5  | 唯一键 `(vendor_code, model_key)` 不冲突（编辑时排除本行）                  | `40001`「该厂商下已存在同名模型（唯一键 vendor_code + model_key）：<码> / <模型名>」                          |
| 6  | 能力至少一项、逐项在字典内、序列化后不超过 255 字符                         | `40001`「能力至少选一项」/「能力取值不在字典内：<值>」/「能力清单最长 255 字符…」                             |
| 7  | 上下文窗口与两个限额非负                                                    | `40001`「<字段>不能为负数，当前值 N」                                                                         |
| 8  | 四个价格列非负                                                              | `40001`「<字段>不能为负数，当前值 N」                                                                         |
| 9  | 币种在 `CNY` / `USD` 内                                                     | `40001`「币种取值不在字典内：<值>（取值 CNY / USD）」                                                         |
| 10 | 状态在 `ENABLED` / `DISABLED` 内                                            | `40001`「状态取值不在字典内：<值>（取值 ENABLED / DISABLED）」                                                |
| 11 | 生效区间两段可解析（`yyyy-MM-dd` 或 `yyyy-MM-ddTHH:mm:ss`），且开始早于结束 | `40001`「<字段>格式不合法：<值>，按 yyyy-MM-dd 或 yyyy-MM-ddTHH:mm:ss 传入」/「生效开始时间必须早于结束时间」 |
| 12 | 备注不超过 512 字符                                                         | `40001`「备注最长 512 字符，当前 N」                                                                          |

**留空的回落口径**：展示名留空回落成模型名（`display_name` 是 `NOT NULL` 列）；状态留空时新增取 `ENABLED`、编辑保持行上原值；币种留空时新增取 `CNY`、编辑保持行上原值。文本列一律去首尾空白后入库。

**覆盖式更新（`updateAll`）**：编辑把校验后的业务列写进一个新的实体（只带主键与业务列），由 `KbModelDbService.updateAll` 落库。MyBatis-Plus 的实体更新策略跳过 `null`，**被清空的列由更新条件里的 `set(列, null)` 显式写成 `NULL`** —— 价格与限额可以真正清空，而不是"留空保持原值"。公共字段由 `KnowledgeMetaObjectHandler` 在实体上填 `update_by` / `update_time`。

## 三、启停

`PATCH /admin/model/models/{id}/status`：取行（取不到 `40464`）→ 解析目标状态（留空或非法回 `40001`）→ `KbModelDbService.updateStatus` 定点回写 `status` 一列 → 写审计（`ENABLED` 记启用、`DISABLED` 记停用）。**启停不动价格、限额与生效区间**，也不改配置。

停用的模型不再进候选集（目录端口按 `status = 'ENABLED'` 筛），已生效的调用不受影响；再次启用后重新进候选。

## 四、试连

`POST /admin/model/models/{id}/probe`（`ModelAdminServiceImpl.probe`）：

1. 取行（取不到 `40464`）；按 `capabilities` 切分能力集合。**与状态无关**，停用的模型也能试连。
2. 按能力选一次最小真实请求，三组各取一种：

| 命中能力                     | 走的模态与入参                                                                 |
|------------------------------|--------------------------------------------------------------------------------|
| `CHAT`                       | `ModelInvoker.chat`：一条 `USER` 消息「ping」，输出约束留空（TEXT 口径不校验） |
| `EMBEDDING`（未命中 `CHAT`） | `ModelInvoker.embed`：一条短文本「ping」                                       |
| 视觉三能力（未命中前两组）   | `ModelInvoker.vision`：一枚内置 1×1 PNG 字节 + `image/png` + 提示词「ping」    |

   视觉优先序固定为 `TABLE_STRUCTURE` → `OCR` → `LAYOUT`（取第一个命中的能力）。图像字节的正式来源见待办 `MODEL-14`，接通前这一步用一枚 69 字节的常量 PNG。

3. **耗时**从调用前取一次墙钟、调用返回（或抛出）后再取一次，单位毫秒；失败也给出到失败为止的耗时。
4. **结论文本**：可用读「可用 · <耗时>ms · <模型>[ · <版本>]」，失败读「失败 · <耗时>ms · <错误码> · <消息>」，截到 255 字符（`probe_result` 列宽）。
5. **回写**：`KbModelDbService.recordProbe(id, 本次时间, 结论文本)` 定点写 `probe_at` / `probe_result` 两列，**成功与失败都写**。
6. **返回**：`ModelProbeVO`，失败时 `available = false`、`errorCode` 取 `KnowledgeException` 的错误码名、`message` 取异常消息；接口本身仍是 200 + `R.code = 0`。未识别的运行时异常按 `40500`（`SYSTEM_ERROR`）记进同两个字段，不改成接口失败。

   试连会产生**一次真实调用**，会在 `kb_model_call_log` 落一行明细（成功与失败都落），能力列按本次模态记。用量视图的「调用总数」包含试连次数。

7. 三组能力都不命中（行的能力串为空或只有未知取值）时按 `40460`（`MODEL_MODALITY_UNSUPPORTED`）记进结果并回写结论，不发请求。

## 五、厂商只读清单

`GET /admin/model/vendors`（`ModelAdminServiceImpl.vendors`）：读 `ModelVendorProperties` 的 `vendors` 映射（`knowledge.model.vendors.<厂商码>`），逐项给出：

| 字段                   | 来源                                                                                           |
|------------------------|------------------------------------------------------------------------------------------------|
| `code`                 | 映射的键                                                                                       |
| `displayName`          | 内置映射（`dashscope` → 阿里百炼、`self-ocr` → 自建推理、`openai` → OpenAI），未命中回落厂商码 |
| `credentialConfigured` | 该厂商配置体里的 `api-key` 是否有非空白值（**只看有没有值，取值不读出**）                      |
| `soleVendor`           | 配置里的厂商数是否为 1                                                                         |

返回前按厂商码升序排序（配置绑定的映射不保证有序）。配置整段缺省时返回空数组。**这条接口只读**：没有新增、编辑与停用厂商的映射，任何写入方法回 405；`api-key` 的内容既不出现在返回体里，也不出现在日志里（日志只打厂商码、模型名与试连结论）。

**启动期校验在启动时已经拦过一遍**（`ModelVendorValidator` 的 D35 / D37 口径）：配置里列出的厂商缺 `api-key`、`auth-type` 不在支持集、`timeout-ms` 不是正数、`base-url` 不是合法 http/https 地址，应用起不来；`vendors` 整段缺省放行。于是运行期看到「未配密钥」的厂商，来源只能是配置在启动之后被改动或环境变量为空（密钥不进库，改了配置需要重启）。

## 六、审计

模型的变更写业务审计（§8.3 的口径）：

| 接口               | 动作（`kb_audit_log.action_type`） | 对象类型（`object_type`） | 前摘要 / 后摘要                     |
|--------------------|------------------------------------|---------------------------|-------------------------------------|
| `POST /models`     | `MODEL_CREATE`                     | `MODEL`                   | 空 / 新增行的 JSON                  |
| `PUT /models/{id}` | `MODEL_UPDATE`                     | `MODEL`                   | 变更前的行 JSON / 覆盖后的行 JSON   |
| `PATCH .../status` | `MODEL_ENABLE` / `MODEL_DISABLE`   | `MODEL`                   | 变更前的行 JSON / 状态改后的行 JSON |

对象 ID 是模型行的主键；摘要由 `JsonUtil.toJsonStr` 生成（`kb_model` 不含密钥，整行可入摘要）。审计与业务写在同一事务里（`@Transactional(rollbackFor = Exception.class)`），业务回滚时审计一并回滚。

**试连不写审计**：它改的是"最近一次试连结论"两列，属于诊断记录而不是模型配置变更。

## 七、涉及的表

| 表                  | 用途                                                                                                                       |
|---------------------|----------------------------------------------------------------------------------------------------------------------------|
| `kb_model`          | 模型目录本体：厂商码、模型名、展示名、能力多值、上下文窗口、四个价格列、币种、两个限额、状态、生效区间、试连结论两列、备注 |
| `kb_model_call_log` | 用量与成本的数据源；试连那次真实调用也在这里落一行（成功与失败都落）                                                       |
| `kb_audit_log`      | 模型新增 / 修改 / 启停留痕：动作 `MODEL_*`、对象类型 `MODEL`、对象 ID 是模型行主键                                         |

表结构定义见 `../../../knowledge-biz/src/main/resources/sql/README.md` 与同目录的 `init.sql`。库表访问与 SQL 片段的单测口径（Mockito 打桩 + `getSqlSegment()` / `getSqlSet()` 断言，仓库没有 DB 测试基建）见 `DbModelCatalogTest` 与本页同批的 `KbModelDbServiceImplTest`。

## 八、权限、异常与边界

- **八条接口逐方法标 `@AdminOnly`**：与 `ModelUsageController` 同一做法（`@PreAuthorize` 判 `ROLE_ADMIN`）。普通用户绕过界面直接调用回 `40104`，未登录回 `40101`；`GlobalExceptionHandler` 与两个 REST 出口保证 HTTP 状态恒为 200 + `R.code`。
- **路径参数不是数字**时类型转换失败，按 `40500` 兜底（与既有接口一致）。
- **`/models` 上没有 DELETE 映射**：模型只启停、不删除，`kb_model` 的逻辑删除标记由库里手工维护。
- **不提供写密钥的入口**：没有 `/credentials` 映射（回 404），也没有任何接收密钥的字段；`ModelSaveDto` 里没有密钥类字段。
- **不改 `application.yml`**：页面的写动作只落 `kb_model` 的业务列与审计，配置（厂商连接、路由参数）始终不动。
