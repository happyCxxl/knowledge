# 自测清单

改完本页（页面、接口、后端逻辑任一）后手工过一遍。前置条件：中间件已起、后端与前端 dev server 已启动；准备一个管理员账号与一个普通用户账号；`knowledge.model.vendors` 里至少配一个厂商（`api-key` 用环境变量注入、`auth-type: BEARER`），`kb_model` 至少有一行 `status = 'ENABLED'`。默认没有配厂商时页面只验证得到「新增模型」的置灰态。

## 入口与权限

- [ ] 管理员登录后，侧栏一级叶子项出现「模型管理」，点击进入 `/model`，页头副标题是「维护可用模型与价格限额；路由按容量占用、健康与延迟自动选型，参数在配置文件」
- [ ] 普通用户登录后，侧栏**看不到**「模型管理」；直接手输 `/model` 被守卫回落到 `/home`
- [ ] 普通用户绕过界面调八条接口中的任一条（`GET /admin/model/models`、`GET /admin/model/vendors`、`POST /admin/model/models`、`PUT /admin/model/models/{id}`、`PATCH /admin/model/models/{id}/status`、`POST /admin/model/models/{id}/probe`、`GET /admin/model/usage/summary`、`GET /admin/model/usage/calls`）→ 都回 `40104`
- [ ] 未登录直接调任一条 → 回 `40101`
- [ ] 管理员的返回按钮回到「首页」

## 二级视图与模型清单

- [ ] 进页面默认停在「模型清单」，徽标数字等于当前清单条数；切到「用量与成本」再切回来，筛选条件与表格数据都还在
- [ ] 表头八列是厂商 / 模型 / 能力 / 价格 / 限额（RPM / TPM）/ 状态 / 最近试连 / 操作，八列等宽
- [ ] 厂商列第一行是展示名、第二行是灰色等宽的厂商码；`dashscope` 一行读「阿里百炼」
- [ ] 一个多能力模型（如 `OCR,LAYOUT,TABLE_STRUCTURE`）在同一行的能力列显示三枚标签
- [ ] 价格列按能力取口径：含 `CHAT` 的行读「输入 / 输出 币种·百万 token」，含 `EMBEDDING` 的行读「单价 币种·千次」，只有视觉能力的行读「单价 币种·页」；四列都空的行读 `—`
- [ ] 限额列读「RPM / TPM」，某项为空读 `—`
- [ ] 能力下拉选 `CHAT` 后只剩含 `CHAT` 的行；选一个没有任何行具备的能力时表格空态读「暂无模型」
- [ ] 状态下拉选「停用」只剩 `DISABLED` 的行；选「启用」只剩 `ENABLED` 的行
- [ ] 关键字输入模型名的一部分能命中（如 `qwen`）；输入展示名的一部分也能命中；输入不存在的串空态读「暂无模型」
- [ ] 点「重置」后三个条件都清空并重新查询；点「查询」按当前条件重查；刷新按钮请求期间禁用并旋转
- [ ] 表头冻结、表体内部滚动，页面整体不出现纵向滚动条
- [ ] 页脚左侧读「共 N 条」，右侧一行说明「试连发一次最小真实请求，结论写回模型行」

## 新增与编辑

- [ ] 点「新增模型」打开右侧抽屉，标题「新增模型」，第一段说明文案里含「本页不涉及密钥」
- [ ] 抽屉里**没有**密钥、密钥掩码、接口地址这三个字段，也没有「接入配置」这类 tab
- [ ] 厂商下拉的选项只来自配置：选项文案形如「阿里百炼（dashscope）· 已配密钥」，配置里没配密钥的厂商读「未配密钥」
- [ ] 厂商下拉里没有任何"新建厂商"入口；把配置里的厂商删掉一个后重启并重进页面，该厂商从选项里消失
- [ ] 配置里一个厂商都没有时：「新增模型」置灰（悬停给出提示）、抽屉里的厂商下拉禁用且占位「暂无已配置的厂商」
- [ ] 配置里只有一个厂商时，打开抽屉默认选中它
- [ ] 模型名留空点「保存」→ 就地提示「请输入模型名」，不发请求
- [ ] 能力一项都不选点「保存」→ 就地提示「至少选择一项能力」
- [ ] 模型名填 129 个字符 → 就地提示最长 128 字符
- [ ] 展示名留空保存 → 清单里该行第一行读模型名（服务端回落生效）
- [ ] 价格或限额填负数（用键盘输入负号绕过控件最小值）→ 就地提示「<字段>不能为负数」，不发请求
- [ ] 保存成功 → 提示「已新增模型」，抽屉关闭，清单与徽标数字一起更新
- [ ] 用同一个「厂商码 + 模型名」再新增一次 → 提示里含「唯一键」，清单不变
- [ ] 绕过界面把 `vendorCode` 改成配置里没有的码调新增 → 回 `40461`，消息含 `knowledge.model.vendors` 与该厂商码
- [ ] 绕过界面把 `capabilities` 传成 `["RERANK"]` → 回 `40001`，消息含「能力取值不在字典内」
- [ ] 绕过界面把 `status` 传成 `PAUSED`、`currency` 传成 `EUR` → 都回 `40001`，消息分别含 `ENABLED` 与 `CNY`
- [ ] 绕过界面把生效区间传成开始晚于结束 → 回 `40001`，消息含「生效开始时间必须早于结束时间」
- [ ] 行内点「编辑」：抽屉标题读「编辑模型 · <模型名>」，字段是行上的现值（含生效区间与备注）
- [ ] 编辑时把输入单价清空保存 → 重新打开抽屉该字段为空，且库里 `price_in_per_m` 是 `NULL`（**留空即写空**，不是保持原值）
- [ ] 编辑时把状态与币种留空（绕过界面传 `null`）→ 行上的状态与币种保持原值
- [ ] 编辑时把厂商换成另一家（配置里有）→ 保存成功，清单里厂商列跟着变
- [ ] 编辑一个不存在的 id → 回 `40464`；请求体缺 `modelKey` → 回 `40001`
- [ ] 请求体整个不发（`POST /admin/model/models` 无 body）→ 回 `40001`「请求体缺失」

## 启停与试连

- [ ] 行内点「停用」→ 提示「已停用模型」，该行状态变灰标「停用」；库里 `status = 'DISABLED'`
- [ ] 停用后再点「启用」→ 提示「已启用模型」，状态回绿标；库里 `status = 'ENABLED'`
- [ ] 停用的模型不再进候选集：把某个模型停用后，走一次需要该能力的调用（例如嵌入）确认它不被选中（可看 `kb_model_call_log` 的模型列）
- [ ] 行内点「试连」（对话模型）→ 按钮进入 loading，随后弹提示「试连可用 · <耗时>ms · CHAT · <模型>」，清单「最近试连」列刷新成「时间 · 可用 · …」
- [ ] 试连一个停用的模型也能成功（试连与状态无关）
- [ ] 试连一个只在配置里配了错密钥的模型 → 提示「试连失败 · … · MODEL_AUTH_FAILED · …」，清单里那一行的结论也变成失败文案
- [ ] 试连一个未声明的能力都没有的行（直接把库里 `capabilities` 改成空）→ 结果 `errorCode` 读 `MODEL_MODALITY_UNSUPPORTED`，接口本身仍回 200
- [ ] 试连一个视觉模型（只有 `OCR` / `LAYOUT` / `TABLE_STRUCTURE`）→ 走视觉模态，结果里 `capability` 读 `TABLE_STRUCTURE` / `OCR` / `LAYOUT` 之一
- [ ] 试连一个嵌入模型 → 走向量模态，结果里 `capability` 读 `EMBEDDING`
- [ ] 试连后核对 `kb_model`：`probe_at` 与 `probe_result` 都被刷新，**失败那次也刷新**
- [ ] 试连后核对 `kb_model_call_log`：多了一行（能力列是本次模态），说明试连也是一次真实调用
- [ ] 试连一个不存在的 id → 回 `40464`
- [ ] 后端日志里只出现厂商码、模型名与试连结论，**找不到密钥取值**

## 用量与成本

- [ ] 切到「用量与成本」→ 首次进入才取数；日期区间默认两段都是今天
- [ ] 四张概览卡的标签是「调用总数」「已知成本合计」「未知用量占比」「切换次数（按 route_reason）」，数值与副文案按接口返回渲染；区间内没有调用时数值读 `—`
- [ ] 选一个跨度更大的区间（如近 7 天）后重查，概览与明细一起变
- [ ] 能力 / 路由原因下拉能过滤明细；路由原因选「降级切换」（`FALLBACK_FROM`）后只剩该原因的行
- [ ] 明细表头九列是时间 / 业务 / 能力 / 模型 / 用量（入 / 出）/ 成本 / 延迟 / 路由原因 / 状态，九列等宽
- [ ] 「业务」列当前读 `—`（`bizType` / `bizId` 写空）
- [ ] 未知用量的行（`usage_unknown = 1`）「用量」与「成本」两列都读 `NULL` 并压暗；确实为零的行读 `0` 而不是 `NULL`
- [ ] 失败行的状态是红标（失败 / 超时 / 限流 / 熔断），悬停能看到 `errorCode`
- [ ] 明细按调用时间倒序，最多 500 条；`limit` 传 3000 时后端按上限 2000 截断
- [ ] 「切换次数」等于明细里 `route_reason` 非 `OK` 的行数；副文案列出各原因与条数，没有切换时读「最近 N 条明细里没有切换」
- [ ] 时间范围不传或格式不合法 → 回 `40001`，消息指出是 `from` 还是 `to`
- [ ] 区间内没有任何调用时，明细空态读「暂无调用明细」
