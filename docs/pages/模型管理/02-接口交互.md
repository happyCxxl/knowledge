# 接口交互

八条接口都是管理员接口（`ModelAdminController` 六个方法、`ModelUsageController` 两个方法，各自标了 `@AdminOnly`），非管理员调用回 `40104`；业务失败同样是 HTTP 200 + `R.code`，提示由请求层拦截器弹出，页面代码只看成功分支（`catch {}` 留空）；通用口径（响应体形状、错误码分段、401 处理、Long 阈值序列化）见 `../../README.md` 的「全局约定」章。

| 触发                        | 前端调用链                                                               | 接口                                    | 请求体           | 响应 `data`             |
|-----------------------------|--------------------------------------------------------------------------|-----------------------------------------|------------------|-------------------------|
| 进页面 / 查询 / 重置 / 刷新 | `ModelManagementView.loadModels` → `api/model.getModelList`              | `GET /admin/model/models`               | 查询参数三项     | `ModelItemVO[]`（清单） |
| 进页面                      | `ModelManagementView.loadVendors` → `api/model.getModelVendorList`       | `GET /admin/model/vendors`              | —                | `ModelVendorVO[]`       |
| 抽屉点「保存」（新增）      | `ModelManagementView.handleSubmit` → `api/model.addModel`                | `POST /admin/model/models`              | `ModelSaveDto`   | `ModelItemVO`           |
| 抽屉点「保存」（编辑）      | `ModelManagementView.handleSubmit` → `api/model.updateModel`             | `PUT /admin/model/models/{id}`          | `ModelSaveDto`   | `ModelItemVO`           |
| 行内点「启用 / 停用」       | `ModelManagementView.handleToggleStatus` → `api/model.updateModelStatus` | `PATCH /admin/model/models/{id}/status` | `ModelStatusDto` | `ModelItemVO`           |
| 行内点「试连」              | `ModelManagementView.handleProbe` → `api/model.updateModelProbe`         | `POST /admin/model/models/{id}/probe`   | —                | `ModelProbeVO`          |
| 首次切到用量视图 / 查询     | `ModelManagementView.loadUsage` → `api/model.getModelUsageSummary`       | `GET /admin/model/usage/summary`        | 查询参数六项     | `ModelCallLogSummary`   |
| 同上                        | `ModelManagementView.loadUsage` → `api/model.getModelUsageCalls`         | `GET /admin/model/usage/calls`          | 查询参数七项     | `ModelCallLogView[]`    |

六条模型与厂商接口挂在 `@RequestMapping("/admin/model")` 下，两条用量接口挂在 `/admin/model/usage` 下；路径都**不带 `api` 段**（仓库既有接口一律不带，`web` 的 `http.ts` 里 `baseURL` 是空串）。`/admin` 前缀在 Vite 开发代理里已配（`../../../web/vite.config.ts` 的 `^/admin/`）。

**没有的接口**（对应页面上没有的入口）：`/admin/model/credentials` 与任何密钥读写（密钥不在库、页面不涉及）、`/admin/model/route-policies`（路由参数在 `application.yml`）、厂商的新增与编辑（厂商是配置里的一个键，不是库里的实体）、模型的删除。

成功响应的 `R.msg`：清单 / 厂商 / 试连用默认文案「操作成功」，新增回「新增成功」，编辑回「保存成功」，启停回「状态已更新」。

## 请求字段

### `GET /admin/model/models` 查询参数

| 参数         | 类型   | 必填 | 说明                                                                   |
|--------------|--------|------|------------------------------------------------------------------------|
| `capability` | string | 否   | 能力字典名（大小写不敏感）；留空不按能力过滤，取值不在字典内回 `40001` |
| `status`     | string | 否   | `ENABLED` / `DISABLED`（大小写不敏感）；留空不过滤，取值非法回 `40001` |
| `keyword`    | string | 否   | 在模型名与展示名两列上做模糊匹配；去首尾空白，空白即不传               |

### `ModelSaveDto`（新增与编辑共用）

| 字段                | 类型         | 必填 | 说明                                                                                     |
|---------------------|--------------|------|------------------------------------------------------------------------------------------|
| `vendorCode`        | string       | 是   | 厂商码；**必须出现在 `knowledge.model.vendors` 里**，不在配置里回 `40461`                |
| `modelKey`          | string       | 是   | 厂商侧模型名，最长 128 字符；与 `vendorCode` 组成唯一键                                  |
| `displayName`       | string\|null | 否   | 展示名，最长 128 字符；留空由服务端回落成 `modelKey`                                     |
| `capabilities`      | string[]     | 是   | 能力字典名数组，至少一项；未知取值回 `40001`；落库形态是逗号分隔的多值串                 |
| `contextWindow`     | number\|null | 否   | 上下文窗口（tokens），非负整数                                                           |
| `priceInPerM`       | number\|null | 否   | 输入每百万 token 单价，非负                                                              |
| `priceOutPerM`      | number\|null | 否   | 输出每百万 token 单价，非负                                                              |
| `priceImagePerPage` | number\|null | 否   | 图像按页单价，非负                                                                       |
| `pricePer1kCalls`   | number\|null | 否   | 嵌入按千次单价，非负                                                                     |
| `currency`          | string\|null | 否   | `CNY` / `USD`（大小写不敏感，落库取大写）；留空时新增取 `CNY`、编辑保持行上原值          |
| `rpmLimit`          | number\|null | 否   | 每分钟请求数上限，非负整数                                                               |
| `tpmLimit`          | number\|null | 否   | 每分钟 token 上限，非负整数                                                              |
| `status`            | string\|null | 否   | `ENABLED` / `DISABLED`（大小写不敏感，落库取大写）；留空时新增取 `ENABLED`、编辑保持原值 |
| `effectiveFrom`     | string\|null | 否   | 生效开始时间，`yyyy-MM-dd`（按当日零点）或 `yyyy-MM-ddTHH:mm:ss`；留空 = 立即生效        |
| `effectiveTo`       | string\|null | 否   | 生效结束时间，写法同上；留空 = 长期有效；两段都填时必须 `from < to`                      |
| `remark`            | string\|null | 否   | 备注，最长 512 字符                                                                      |

编辑（`PUT`）是**覆盖写**：请求体里给 `null` 的数值列会把那一列写成 `NULL`（价格与限额可以清空）；`status` 与 `currency` 给 `null` 则保持行上原值。唯一键判定会排除本行。

### `ModelStatusDto`（启停）

| 字段     | 类型   | 必填 | 说明                                         |
|----------|--------|------|----------------------------------------------|
| `status` | string | 是   | `ENABLED` / `DISABLED`；留空或非法回 `40001` |

### 用量两个接口的查询参数

| 参数          | 类型   | 必填 | 说明                                                                                 |
|---------------|--------|------|--------------------------------------------------------------------------------------|
| `from` / `to` | string | 是   | 时间范围，左闭右开；`yyyy-MM-dd`（按当日零点）或 `yyyy-MM-ddTHH:mm:ss`；缺一不可     |
| `tenantId`    | number | 否   | 租户 ID                                                                              |
| `capability`  | string | 否   | 能力字典名                                                                           |
| `model`       | string | 否   | 模型名（精确匹配）                                                                   |
| `routeReason` | string | 否   | 路由原因字典名                                                                       |
| `status`      | string | 否   | 调用状态字典名                                                                       |
| `limit`       | number | 否   | **只对 `/calls` 生效**：未传按 500，上限 2000，超过按上限截断；`/summary` 忽略该参数 |

页面在用量视图固定下发 `from` = 选中开始日、`to` = 选中结束日的次日、`limit` = 500。

## 响应字段

### `ModelItemVO`（清单一项）

| 字段                | 类型         | 说明                                               |
|---------------------|--------------|----------------------------------------------------|
| `id`                | string       | 主键（雪花 ID 按字符串下发）                       |
| `vendorCode`        | string       | 厂商码                                             |
| `vendorName`        | string       | 厂商展示名（服务端内置映射；未命中回落厂商码本身） |
| `modelKey`          | string       | 厂商侧模型名                                       |
| `displayName`       | string       | 展示名（落库非空，留空过的一律已回落成模型名）     |
| `capabilities`      | string[]     | 能力字典名清单                                     |
| `contextWindow`     | number\|null | 上下文窗口                                         |
| `priceInPerM`       | number\|null | 输入每百万 token 单价                              |
| `priceOutPerM`      | number\|null | 输出每百万 token 单价                              |
| `priceImagePerPage` | number\|null | 图像按页单价                                       |
| `pricePer1kCalls`   | number\|null | 嵌入按千次单价                                     |
| `currency`          | string       | 币种                                               |
| `rpmLimit`          | number\|null | 每分钟请求数上限                                   |
| `tpmLimit`          | number\|null | 每分钟 token 上限                                  |
| `status`            | string       | 状态码值                                           |
| `effectiveFrom`     | string\|null | 生效开始时间（ISO-8601）；空表示立即生效           |
| `effectiveTo`       | string\|null | 生效结束时间（ISO-8601）；空表示长期有效           |
| `probeAt`           | string\|null | 最近一次试连时间；从未试连为空                     |
| `probeResult`       | string\|null | 最近一次试连的结论一行文本（成功与失败都写）       |
| `remark`            | string\|null | 备注                                               |

清单按厂商码升序、模型名升序返回（`ORDER BY vendor_code, model_key`），页面不排序、不分页。

### `ModelVendorVO`（厂商下拉一项）

| 字段                   | 类型    | 说明                                                         |
|------------------------|---------|--------------------------------------------------------------|
| `code`                 | string  | 厂商码（`knowledge.model.vendors` 下的键）                   |
| `displayName`          | string  | 厂商展示名（内置映射；未命中回落厂商码本身）                 |
| `credentialConfigured` | boolean | **是否已配密钥**：只看配置里的 `api-key` 有没有值            |
| `soleVendor`           | boolean | 配置里是否只有这一个厂商（页面据此决定新增时默认选中哪一项） |

**返回体里没有密钥字段，也没有密钥取值**：这一份 VO 只有上面四项，配置里的 `api-key` 内容不出接口、不进日志。清单按厂商码升序返回；配置里没有厂商时返回空数组。

### `ModelProbeVO`（试连结果）

| 字段           | 类型         | 说明                                                                            |
|----------------|--------------|---------------------------------------------------------------------------------|
| `available`    | boolean      | 本次最小真实请求是否成功返回                                                    |
| `latencyMs`    | number       | 本次调用耗时（毫秒；失败时给出到失败为止的耗时）                                |
| `capability`   | string       | 本次试连用的模态（`CHAT` / `EMBEDDING` / `OCR` / `LAYOUT` / `TABLE_STRUCTURE`） |
| `model`        | string\|null | 响应回传的模型标识（失败为空）                                                  |
| `modelVersion` | string\|null | 响应回传的模型版本（响应不带时为空）                                            |
| `errorCode`    | string\|null | 失败时的错误码名（成功为空）                                                    |
| `message`      | string\|null | 失败原因（成功为空）                                                            |
| `probeAt`      | string       | 本次试连时间（与回写 `kb_model.probe_at` 同一个值）                             |
| `probeResult`  | string       | 回写到 `kb_model.probe_result` 的结论一行文本                                   |

**试连失败不是接口失败**：请求照常回 200 + `R.code = 0`，可用性读 `available`，原因读 `errorCode` / `message`，页面据此弹失败提示。这样一次探测的两种结论走同一条返回形状，页面也就能把耗时与模态一起显示出来。

结论一行文本的形态：可用读「可用 · <耗时>ms · <模型>[ · <版本>]」，失败读「失败 · <耗时>ms · <错误码> · <消息>」，超长截到 255 字符（列宽上限）。

### `ModelCallLogSummary`（用量概览）

| 字段               | 类型         | 说明                                                               |
|--------------------|--------------|--------------------------------------------------------------------|
| `calls`            | number\|null | 调用总数                                                           |
| `successCalls`     | number\|null | 成功数（`status = SUCCESS`）                                       |
| `failedCalls`      | number\|null | 失败数（`status` 不是 `SUCCESS` 的全部）                           |
| `timeoutCalls`     | number\|null | 超时数                                                             |
| `rateLimitedCalls` | number\|null | 被限流数                                                           |
| `unknownCalls`     | number\|null | 用量未知的条数（`usage_unknown = 1`）                              |
| `unknownRatio`     | number\|null | 未知占比（四位小数，`0.0081` 读 0.81%）；范围内没有调用时为 `null` |
| `totalTokens`      | number\|null | 已知 token 合计（全为未知时为 `null`）                             |
| `costTotal`        | number\|null | 已知成本合计（全为未知或单价缺失时为 `null`）                      |

未知行（三项 token 与 `cost` 记 `NULL`）被 `SUM` 天然跳过，不参与合计；「无数据」与「全部已知」不混用（前者聚合列为 `null`）。

### `ModelCallLogView`（明细一行）

在写入字段之上补 `id` 与 `createTime`（明细写入时刻，紧随调用结束）。页面用到的几项：`createTime`、`bizType` / `bizId` / `traceId`（当前写空）、`capability`、`vendor`、`model`、`modelVersion`、`promptTokens` / `completionTokens` / `totalTokens`、`usageUnknown`、`unitPriceIn` / `unitPriceOut` / `currency`、`cost`、`latencyMs`、`retryCount`、`fallbackFrom`、`routeReason`、`cacheHit`、`status`、`errorCode`。

字段口径（与 §4.5 一致）：

- 用量三项与 `cost` 为 `null` 表示**未知**（配 `usageUnknown = 1`），为 `0` 表示**确实为零**，两者语义不同、不可混用。
- `cost` 只对 `CHAT` 落金额；`EMBEDDING` 的 token 照记而 `cost` 留空；OCR / 版面 / 表格结构按 D34 强制 `NULL + usageUnknown = 1`。
- `latencyMs` 是一次逻辑调用的整段耗时（含底层实例内的重试与退避等待）；`retryCount` 由 HTTP 层计数（尝试次数 − 1）。
- `routeReason` 为空的两种情形：调用没经选型（形参直接给厂商码），或那一行由本片之前的实现写入。

## 本页可能出现的失败

| code  | 触发场景                                                                                                                                                                                                                                                                        |
|-------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 40001 | 请求体缺失或 JSON 格式错误；模型名缺失或超长；能力为空或不在字典；状态 / 币种取值非法；价格或限额为负；生效区间格式不合法或开始不早于结束；备注或展示名超长；唯一键 `(vendor_code, model_key)` 冲突；用量查询的时间范围缺失或格式不合法；能力 / 路由原因 / 调用状态取值不在字典 |
| 40101 | 未认证（令牌缺失或已失效）                                                                                                                                                                                                                                                      |
| 40104 | 非管理员调用八条接口中的任一条                                                                                                                                                                                                                                                  |
| 40461 | 保存时厂商码不在 `knowledge.model.vendors` 里（消息带配置键与已配置厂商清单）                                                                                                                                                                                                   |
| 40464 | 路径里的 `{id}` 查不到模型行（编辑 / 启停 / 试连）                                                                                                                                                                                                                              |
| 40500 | 系统异常兜底；路径里的 `{id}` 不是数字（类型转换失败）                                                                                                                                                                                                                          |

试连过程中的调用失败（`40462` 鉴权失败、`40465` 限流、`40466` 超时、`40467` 服务端错误、`40468` 网络不可达、`40463` 参数或内容被拒、`40460` 模型未声明可测试的能力、`40461` 运行期厂商配置缺失）**不走上表**：它们出现在 `ModelProbeVO.errorCode` 里，接口本身回 200 + `R.code = 0`。
