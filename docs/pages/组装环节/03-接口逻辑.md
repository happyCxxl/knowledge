# 接口逻辑

本文件写「后端拿到请求之后到底做了什么」。涉及的表是 `kb_file_result`（文件结果）、`kb_pipeline_task`（环节任务）与 `kb_pipeline_product`（产物），字段定义见 `../知识库列表/03-接口逻辑.md`；通用机制（错误码分段、鉴权、分页、归属校验）见 `../../README.md` 的「全局约定」章与 `../解析环节/03-接口逻辑.md`，本页不复述。

## Controller 划分

| Controller                         | 管什么                                                                                                   |
|------------------------------------|----------------------------------------------------------------------------------------------------------|
| `KnowledgeFileStructureController` | 组装环节专属：触发组装 `POST /{fileResultId}/structure`、组装详情 `GET /{fileResultId}/structure-detail` |
| `KnowledgeFileStageController`     | **各环节共用**的产物内容 `GET /{fileResultId}/stage-content`（白名单五环节同一入口）                     |

两者都以 `/file-results` 为类级前缀。归属校验（`FileResultAccessGuard`）与解析环节同源，覆盖 `/file-results/{fileResultId}/...` 前缀的全部接口。

## `POST /file-results/{id}/structure`

`KnowledgeFileStructureController.structure` → `StructureControlServiceImpl.structure`：

1. 按 `fileResultId` 取文件结果，取不到抛 **40432**；过归属校验；
2. 解析上游解析产物 `requireParseProduct`：传了 `upstreamProductId` 就按它取，并校验存在、环节为 `PARSE`、且属于该文件结果（任一不满足 → **40432**）；不传取该文件结果最新的 `PARSE` 产物；
3. 一条解析产物都没有 → **40432**，消息「解析产物不存在，请先触发解析」；
4. `TaskTriggerSupport.trigger(…, banOnSuccess=false)`：`RUNNING` → **40431**；`QUEUED` → 补投唤醒既有任务；其余终态或无任务 → 新建一条 `QUEUED` 任务（`upstream_product_id` 记下这次选定的解析产物）并入队。

**旧任务与旧产物一律保留**：重新触发不清历史，血缘上表现为同一份文件上的多条组装运行。

## `GET /file-results/{id}/structure-detail`

`StructureControlServiceImpl.structureDetail`：

1. 取文件结果（40432）→ 归属校验；
2. `TaskDetailSupport.resolveTask` 解析目标任务：传了 `taskId` 用它，并校验它属于该文件该环节（不属于则 **40001**）；不传取该环节最新任务；
3. `detailSupport.withTask` 填公共字段：任务状态、起止时间、错误码与说明、子步骤列表；
4. 按 `task.productId` 取该次运行的产物（历史任务同样可展示自己的产物）：有产物则填 `artifactId` / `contentHash` / `capabilitySnapshot`，并读产物本体汇总 `summary`（元素 / 标题 / 段落 / 表格 / 图片 / 关系 / 冲突 / 告警计数）、`warnings`（质量告警文案）、`conflicts`（主路与被裁决方）、`outline`（文档内容大纲）；
5. `stageStats` 与 `stageSummary` 由 `StructureStatsSupport` 现算（见下）；无任务或无产物时 `outline` / `warnings` / `conflicts` 是空列表、`summary` 与 `stageStats` 为 null、`stageSummary` 取决于状态（进行中为空）。

`stage-content` 的读取路径（白名单校验、参数归一、按 `task.productId` 取产物、过滤先于分页、`truncated` 口径）与解析环节同一份实现，区别只在组装元素的 `extra`：`level` / `page` / `rows` / `cols` / `bbox`，`alignKey` 是产物元素 ID。

## 组装执行链（`StructureTaskRunner` → `AssemblerPipeline`）

执行器领任务后读上游 `ParseResult` 产物，交给组装管线；管线是纯算法，不碰 DB 与对象存储：

| 步骤             | 做什么                                                                                                                                                                                                                                                                                                                                                                                                                   | 产出                                                |
|------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------|
| ① 元素标准化     | `NormalizerImpl`：解析元素 → 统一元素（类型映射、全局 ID = 类型前缀 + 内容哈希、单元格嵌套、扩展区与溯源透传、目录行标记透传）                                                                                                                                                                                                                                                                                           | `UnifiedElement` 列表                               |
| ② 去重与合并     | `DedupMergerImpl`：IoU + 文本相似度**双判定**，按来源顺序取舍；来源键语义为 `source` = 来源路名（`native` / `ocr` / …）、`provider` = 具体解析器；来源顺序属**临时口径**（接入第二路后改按证据裁决，业界无公开优先级表）；同框不同内容且无法裁决 → 两路都留并标 `PRIMARY` / `BACKUP` + 冲突记录                                                                                                                          | 元素列表 + 合并对数 + 冲突记录                      |
| ③ 阅读顺序       | `ReadingOrderResolverImpl`：有坐标元素按页分组、页内 XY-cut（横向切行带 → 带内纵向切块 → 块内递归）；无坐标元素保持解析顺序直通                                                                                                                                                                                                                                                                                          | 阅读顺序列表                                        |
| ④ 结构组装       | `StructureAssemblerImpl`：标题推定规则链（样式 → 章级 → 单级数字 → 多级数字 → 中文括号 → 中文顿号 → 字号加粗，命中即止；样式名锚定匹配且级数收敛到 1~9、编号规则需含 CJK 且有字号佐证才定级、模型兜底默认关闭） + 关系构建（Excel 章节与表格交错插入、同级章节互为兄弟、关系按类型与端点去重）                                                                                                                           | 标题（`type` / `level` / 判定证据）、候选计数、关系 |
| ⑤ 跨页接续       | `TableContinuationResolverImpl`：仅 PDF 表格；主规则 = 相邻页（按当前末页比较）+ 上页表尾 + 下页页首 + 表头可读且相似 + 列数相同；表头不可读时不进主规则，放宽规则按参考行（表头不可读时用首行）的列宽模式一致 → 疑似接续；合并结果保留首页 `page` 与 `bbox`，跨页位置由 `pageRange` / `bboxes` 逐页累积，同一张表可链式跨任意页数；续页行按保留行序号重编号（表头未判定时不跳行，行数 = 声明行数 − 实际丢弃的表头行数） | 合并后的表格 + `CONTINUATION_OF` 关系 + 疑似计数    |
| ⑥ 溯源校验       | 统计「文件引用 + 定位路径齐备」的元素占比，写进组装报告                                                                                                                                                                                                                                                                                                                                                                  | 可溯源比例（覆盖率告警阈值 1.0）                    |
| ⑦ 重复与噪声识别 | `RepeatNoiseMarkerImpl`：重复页（页文本 bigram Jaccard 超阈值）、重复段（相似度超阈值且长度达标，排除页眉页脚）、噪声页（无元素 / 仅图片 / 乱码率超阈值；页覆盖范围按 `pageRange` 计）                                                                                                                                                                                                                                   | 元素 `marks` 与页 `marks`（只标记，不改结构）       |

随后构建 `UnifiedDocument`：`documentInfo`（`documentId` = `doc-{fileResultId}`、源文件引用与类型、上游解析运行 ID、产物 `schemaVersion`、能力快照）、`pages`（取首个带页面尺寸的解析来源）、`elements`、`relations`；再挂 `quality`（冲突记录 + 五类告警：`TITLE_CANDIDATE` / `SUSPECTED_CONTINUATION` / `PROVENANCE_MISSING` / `NOISE_PAGE` / `ELEMENT_TYPE_UNMAPPED`）。

### 关系类型

| 关系                | 由谁构建                             | 含义                                              |
|---------------------|--------------------------------------|---------------------------------------------------|
| `PARENT_CHILD`      | 结构组装（章节树）+ Excel sheet 归并 | 标题 / 章节节点指向其子内容                       |
| `NEXT` / `PREVIOUS` | 结构组装（阅读顺序）                 | 正文阅读顺序链，**页眉页脚排除在外**（仍在树内）  |
| `TABLE_CELL_OF`     | 结构组装                             | 单元格 → 所属表格                                 |
| `CONTINUATION_OF`   | 跨页接续                             | 续表后续页 → 首页；`from` / `to` 带 `#p页码` 后缀 |

`CAPTION_OF` / `DERIVED_FROM` 是字典里预留、当前不产出的类型。

### 终态与落库

`TaskRunnerSupport.complete` 按管线的建议状态分派：

- **成功**：写产物（对象存储 sha256 寻址）+ `kb_pipeline_product` 行（`upstream_product_id` = 本次选定的解析产物）+ 子步骤记录，任务置 `SUCCESS`；
- **失败**（含空树与上游不可读）：**写子步骤记录、不写产物与产物行**，任务置 `FAILED` 并落 `errorCode` / `errorMsg`（原因截断到 1000 字符）。

空树判定在管线末尾：`elements` 为空 → `STRUCTURE_EMPTY` + 「无任何可组装元素（空树）」；**组装不产出 `PARTIAL_SUCCESS`**。上游失败有四种入口，统一落 `STRUCTURE_UPSTREAM_UNREADABLE`：任务未指定上游且该环节没有产物、产物对象读不出、产物 JSON 反序列化为空、解析产物本体或其文件信息缺失。

## 组装统计（`StructureStatsSupport`）

**统计在读取侧现算**：执行树的组装节点与组装详情共用同一份口径，纯读取，不落库、不改产物、不进能力快照。产物读不到时统计为 null，摘要为 null —— 「结构可用」这类断言只在统计到手时成立。

- `readDocument(fileStorage, artifactId)`：产物引用为空、对象读不到、JSON 解析失败一律返回 null；
- `stats(startedAt, finishedAt, document)`：按产物现算全部键（键名与含义见 `02-接口交互.md`）；`chapterCount` 按「有 `SECTION` 节点用章节节点数，没有时用一级标题数」；`withoutBboxCount` 是阅读顺序的推断口径；`continuationFromPage` / `continuationToPage` 从 `CONTINUATION_OF` 关系的 `#p页码` 后缀取最小 / 最大页；`schemaVersion` 取 `documentInfo`；
- `summary(errorMsg, stats, status)`：失败取 `errorMsg`、进行中与统计缺失为 null、空树给「无任何可组装元素（空树）」、有异常项时按「结构可用 · 溯源偏低 N% · 疑似续表 N 处 · 重复与噪声待处置」拼接（阈值常量 80 与实现同源）。

### 统计承载字段的划分

| 承载字段                               | 谁用                                                                           |
|----------------------------------------|--------------------------------------------------------------------------------|
| 通用 `stats`（`Map<String, Object>`）  | 组装节点的全部统计（含 `schemaVersion`）；切片 / 向量化 / 预处理各自的键也走它 |
| 通用 `stageSummary`                    | 组装结论一句话                                                                 |
| 解析专用 `parseStats` / `parseSummary` | 解析环节的固定统计结构与结论（组装不下发）                                     |

**组装统计在通用统计之后落位**：`LineageQueryServiceImpl.toNode` 先构造通用 `stats`（只覆盖切片 / 向量化 / 预处理）并 `node.setStats(stats)` ——**这是一次整份赋值**，随后才由 `fillStructureStats` 用组装统计替换它。顺序反过来会被那次空 map 覆盖，组装节点将没有任何统计；同理组装统计不做增量合并，一个组装节点的 `stats` 要么是完整组装统计，要么是空 map（产物不可读）。

## 只读字段的边界（现状）

- `structure-detail` 只给 `summary` / `warnings` / `conflicts` / `outline` 与公共任务字段，**不下发上游产物 ID**：左栏展示的是组装产物本身；
- `outline` 元素带 `cells`（表格行列明细），**不带溯源字段**：左栏排版不需要按溯源与上游对齐；溯源覆盖率只以统计形式出现；
- 执行树节点与组装详情都不下发 `upstreamProductId`，「基于哪次上游」由链图的边表达；
- `stage-content` 对组装环节的 `extra` 只有 `level` / `page` / `rows` / `cols` / `bbox`，元素身份走 `alignKey`。

## 错误码

| code  | 语义                                                  |
|-------|-------------------------------------------------------|
| 40001 | 参数错误：环节不在白名单、`taskId` 不属于该文件该环节 |
| 40101 | 未认证或令牌无效：无登录上下文                        |
| 40401 | 知识库不存在 / **越权访问**（两者响应一致）           |
| 40431 | 组装任务进行中，请勿重复触发                          |
| 40432 | 文件结果不存在；触发时该文件结果还没有解析产物        |
| 40500 | 系统异常兜底                                          |

任务级错误码落在 `kb_pipeline_task.error_code`：`STRUCTURE_EMPTY`、`STRUCTURE_UPSTREAM_UNREADABLE`、`STRUCTURE_FAILED`。
