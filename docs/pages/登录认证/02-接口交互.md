# 接口交互

三个接口都由请求层统一处理：业务失败也是 HTTP 200 + `R.code`，提示由拦截器弹出，页面代码只看成功分支。通用口径（响应体形状、错误码分段、401 处理）见 `../../README.md` 的「全局约定」章。

## 登录与注册

| 触发        | 前端调用链                                      | 接口                  | 请求体                                              | 响应 `data` |
|-------------|-------------------------------------------------|-----------------------|-----------------------------------------------------|-------------|
| 点「登 录」 | `LoginView.handleSubmit` → `api/auth.getToken`  | `POST /auth/login`    | `{username, password, remember}`                    | 见下表      |
| 点「注 册」 | `LoginView.handleRegister` → `api/auth.addUser` | `POST /auth/register` | `{username, displayName, email?, phone?, password}` | `null`      |

登录响应的 `data`（后端 `LoginVO`，**用户信息全部显式下发**，前端不再解令牌）：

| 字段           | 说明                                         |
|----------------|----------------------------------------------|
| `token`        | 访问令牌（JWT）                              |
| `id`           | 用户主键（雪花 ID，按字符串下发）            |
| `username`     | 登录用户名                                   |
| `displayName`  | 真实姓名（可能为 null）                      |
| `email`        | 邮箱（可能为 null）                          |
| `phone`        | 手机号（可能为 null）                        |
| `status`       | 状态：1 启用 / 0 停用                        |
| `role`         | 角色码值：`ADMIN` / `USER`                   |
| `tokenVersion` | 令牌版本（递增即让该账号已签发令牌全部失效） |

前端把除 `token` 之外的字段连同令牌一起持久化成「用户快照」（键 `knowledge-user`，与令牌同一档存储），刷新页面后据此恢复用户名、真实姓名与角色；令牌解析只保留给过期判断。详见 `01-页面功能.md`。

两点需要留意：

- 登录表单字段名是 `account`，发请求时映射成 `username`；注册表单的 `confirmPassword` 只在前端做一致性校验，**不上送**；邮箱与手机号留空时前端传 `undefined`（即不传该字段）。
- 注册成功后前端不消费任何返回数据，只看 `code` 是否为 0。

## 自助改密

| 项          | 值                                                                          |
|-------------|-----------------------------------------------------------------------------|
| 入口        | 布局壳（`AppLayout`）用户菜单 →「修改密码」，打开 `ChangePasswordDialog`    |
| 前端调用链  | `ChangePasswordDialog.handleSubmit` → `api/user.updatePassword`             |
| 接口        | `PUT /user/password`（`UserController`，**不加 `@AdminOnly`**，对本人开放） |
| 请求体      | `{oldPassword, newPassword}`                                                |
| 响应 `data` | 新令牌（字符串）                                                            |

交互：当前密码 / 新密码 / 确认新密码三个字段，前端校验长度 8-64 位且两次输入一致；成功后调 `authStore.replaceToken` 把响应里的令牌**替换**本地令牌——写回令牌当前所在的那一档存储，不改变「记住我」的选择——并提示「密码已修改，其他设备需用新密码重新登录」。

## 本页可能出现的失败

| code  | 触发场景                                                                        |
|-------|---------------------------------------------------------------------------------|
| 40103 | 用户名或密码错误（**用户不存在、密码错、账号已停用三种情况共用此码**）          |
| 40102 | 注册时用户名已存在                                                              |
| 40001 | 参数校验失败，`msg` 形如 `username 用户名长度须为 3-32 位`（字段名 + 消息拼接） |
| 40110 | 改密时当前密码不正确                                                            |
| 40105 | 改密时当前用户不存在（本人账号已被删除）                                        |
| 40111 | 登录尝试过于频繁（失败计数达阈值，见 `03-接口逻辑.md`）                         |
| 40201 | 请求过于频繁（接口级限流，见 `03-接口逻辑.md`）                                 |
| 40500 | 系统异常兜底                                                                    |

## 登录成功后的落点

令牌存放：勾选「记住我」写 localStorage，否则写 sessionStorage，写入时会清掉另一边的同名键（用户快照同档处理）。

跳转目标由 `takeRedirectTarget()` 取路由上的 `redirect` 查询参数——路由守卫与 `api/http.ts` 遇 40101 的硬跳转都写这个参数；只接受站内路径，非法值或指向登录页时回落 `/home`。
