# 页面功能

给未登录用户使用：登录进入系统，或自助注册一个账号。已登录用户访问此页会被路由守卫送回 `/home`。

界面是一张 3D 翻转舞台（`perspective: 1700px`），两张卡片互为背面：

| 卡片     | 内容                                                                                                                                                                                                     |
|----------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 登录卡   | 账号、密码、记住我（默认勾选）、「忘记密码请联系管理员重置」提示、登录按钮、「立即注册」入口                                                                                                             |
| 注册卡   | 用户名（3-32 位）、真实姓名（必填，最长 64）、密码（8-64 位）、确认密码、邮箱（选填）、手机号（选填）、注册按钮、「直接登录」入口；六个字段按「用户名 + 姓名 / 密码 + 确认 / 邮箱 + 手机号」两列三行排布 |
| 固定元素 | 页脚品牌行                                                                                                                                                                                               |

交互要点（都是代码里有明确理由的部分）：

- 切换卡片是绕 X 轴翻转 520 ms，缓动 `1-(1-t)^4`；系统开启「减少动态效果」时直接落位，不做动画。
- 翻转期间两张脸强制 `opacity: 1` / `visibility: visible`，正反面交给 `backface-visibility` 判定——按角度算透明度会让两张脸各半透明叠出镜像重影。
- 翻转期间给面板加 `.no-frost` 类关掉 `backdrop-filter`，避让 Chromium 在 transform 祖先上的合成异常（会导致整张卡不渲染）。
- 舞台是**固定尺寸**（宽 `min(448px, 100%)`、高 `680px`），两张卡的宽高完全相同，**不随字段多少或校验提示出现而变化**；面板高度固定、内容超出时在面板内滚动，视口比舞台矮时页面（`.login-main`）可滚动且用 `align-items: safe center` 保证顶部不被裁掉。
- 两张卡的面板是 flex 纵向布局，底部两行（切换入口、页脚）用 `margin-top: auto` 靠下对齐，两张卡版式一致。
- 两张卡的表单元素 `tabindex` 随朝向切换为 `-1`，Tab 键不会跳到背面的表单上。
- 表单项留了固定高度的错误位（并排的格子略收），校验提示出现时不会把面板撑高。
- 两个表单都拦掉了原生提交（`@submit.prevent`）：回车即提交，也不会触发浏览器默认提交导致页面重载；请求进行中再按回车会被 `loading` 拦掉，不重复发请求。

两条业务流：

- **登录**：校验表单 → 调登录接口 → 把响应里的令牌与**用户快照**一起写入 store（记住我 → localStorage；否则 sessionStorage）→ 提示「登录成功」→ 跳回被中断前的页面（无暂存则 `/home`）。
- **「记住我」管两件事**：存储档位（勾选 → localStorage，不勾选 → sessionStorage）**和令牌有效期**（勾选 → `ttl-days-remember`，当前 30 天；不勾选 → `ttl-days`，当前 1 天）。选框默认勾选，即默认走长期档。
- **注册**：校验表单 → 调注册接口 → 提示「注册成功，请登录」→ **不自动登录**，翻回登录卡并回填用户名、清空密码（避免浏览器把注册密码当登录凭据留存）。

## 用户信息从哪来

登录成功后，界面展示与菜单渲染所需的用户信息（`username` / `displayName` / `role` / `status` …）**全部来自登录响应**，前端不再解析令牌载荷取这些字段。这些字段随令牌持久化成一份「用户快照」，刷新页面后从快照恢复；令牌本身只在判断过期时被解析（刷新后除令牌外没有别的凭据，`exp` 只能从令牌取）。字段清单见 `02-接口交互.md`。

## 自助改密的位置

入口不在本页，而在布局壳（`AppLayout`）的用户菜单：与「个人信息」并列的「修改密码」。交互与接口见 `02-接口交互.md`，后端步骤见 `03-接口逻辑.md`。
