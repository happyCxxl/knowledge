# 系统设置

仅管理员可进的平台级设置页，页面上是一张小卡「文件服务写入后端」，只做两件事：**列举存储源**与**启用其中一个**——启用某个存储源等于把当前启用的那个换掉，之后的新上传与新任务写到它，读取按对象记录里的数据源 ID 走。数据源**只由 `application.yml` 的 seed 或库内 SQL 维护**，页面不提供新增、编辑、停用、删除与连接测试入口。

| 项         | 值                                                                                                                                                                            |
|------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 路由       | `/settings`（`meta.adminOnly`，非管理员被守卫弹回 `/home`）                                                                                                                   |
| 入口       | 侧栏一级叶子项「系统设置」（菜单项同样带 `adminOnly`）                                                                                                                        |
| 前端视图   | `../../../web/src/views/system/SystemSettingView.vue`                                                                                                                         |
| 前端类型   | `../../../web/src/types/system.ts`（清单与启用响应的契约）                                                                                                                    |
| 前端接口层 | `../../../web/src/api/system.ts`                                                                                                                                              |
| 后端       | `knowledge-biz` 模块的 `StorageSourceController`（三个方法各自标了 `@AdminOnly`，路径前缀 `/system`）                                                                         |
| 涉及接口   | `GET /system/storage-sources`、`POST /system/storage-sources/{id}/current/preview`、`POST /system/storage-sources/{id}/current`                                               |
| 涉及的表   | `kb_storage_source`（数据源本体）、`kb_pipeline_task`（影响面统计）、`kb_file_result` / `kb_source_file` / `kb_file_object`（影响面按链取数据源）、`kb_audit_log`（切换留痕） |

存储数据源是表里的记录：**一行一个实例**，同一种类型可以有多行，连接参数整体落在这一行的 `config_json` 里。对象记录的身份是数据源 ID（`storage_source_id`），行里另存的存储类型码值用于展示与降级。`is_current` 全表至多一行，指向当前启用的那个数据源；`status` 列留在库里，可能有 `DISABLED` 的行，靠 SQL 维护，页面上没有停用与恢复入口。`application.yml` 的 `file-center.minio.*` / `file-center.local.*` 只在数据源表为空时充当 seed 来源（MinIO 与本地磁盘各一行），`file-center.storage-type` 指明 seed 后哪一行是当前启用。

卡内两段：**存储源下拉 + 「启用」按钮**（只列 `ENABLED` 的行，默认选中当前启用项）与「**当前启用**」信息块（名称、类型、参数、状态四态与最近探测时间）。启用走「预览影响面 → 确认启用」两步；密钥类参数不进响应，只体现为「密钥 已配置」一行。

`kb_system_setting` 这张键值表留在库里供以后的普通设置使用，本页的读写都不碰它。

## 待定项

- **回落注册的数据源不在清单里**：表里没有可用行时，后端按 `file-center.storage-type` 组装一条不落库的定义并标记为当前启用；页面的清单来自表，这一条不在其中，下拉没有默认选中项，信息块也没有可展示的存储源。
- **已删除的行仍占着名称唯一键**：`name` 是表级唯一键，逻辑删除不释放它；库内 SQL 维护数据源时，与已删行同名的行插不进去（`uk_name` 冲突）。
- **`configured` 没有界面落点**：状态文案读的是 `registered` 与 `probeOk`，`configured`（必填参数是否齐全）不参与渲染，判断参数是否齐全要看库里的 `config_json`。
- **探测结论只在两处刷新**：页面没有连接测试入口，`last_probe_ok` / `last_probe_at` 只在启动初始化与设为当前时回写；库内把参数改坏之后，状态文案要等下一次启用或下一次重启才会变成「连接失败」。
- **停用的行在页面上不可见**：下拉只列 `ENABLED` 的行，信息块只讲当前启用项，`status = DISABLED` 的行既没有操作入口也不出现在任何一处，恢复可用要先把 `status` 改回 `ENABLED`（改库），再在页面上把它启用。
