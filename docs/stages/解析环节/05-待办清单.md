# 解析环节 · 待办清单

本文件是解析环节待办的**唯一清单**：条目来自本环节的两份现状文档（`README.md` 的待定项）与市面做法对照（`../../research/解析环节-开源方案调研.md` 的审计映射表），按「问题 → 现状证据 → 解决什么」编号列出，供逐条开工与状态跟踪。

## 编号与状态约定

编号四段：`PDF-xx` 解析器（PDF）、`OFF-xx` 解析器（Office）、`PDF-39` / `TASK-xx` 任务与产物编排、`PAGE-xx` 解析页面与接口。`PDF-01`～`PDF-04`、`PDF-38`、`PDF-39` 沿用与用户对话里已用过的编号，其余为按本文件重排后的编号，**编号以本文件为准**。

| 状态 | 含义                                       |
|------|--------------------------------------------|
| 已做 | 代码与文档已落地（附提交号）               |
| 待做 | 方案已明确，可直接开工                     |
| 待定 | 先要定口径才能开工（条目本身即待决策问题） |
| 待核 | 调研列为待改项，尚未在代码里核实是否已落地 |

**本轮范围**：清单内条目全部补齐，模型能力接入（PDF-04）同样在范围内。

## 七、使用方式

开工时从「待做」里取一条：先给问题说明与真实样例（样例放 `samples/`，该目录不入库），确认后改代码 + 补单测，逐条独立提交；**门禁按节统一跑**（每节条目全部做完后跑一次 `mvn -o test`、静态检查四件套、注释口径、编码检查、前端 `pnpm lint`），中间每条只跑针对性的单测。状态与提交号在本文件「已做」表里回填。
