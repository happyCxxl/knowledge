# 解析环节 · 开源方案调研

面向本项目解析环节（PDFBox 3.0.4 + POI 5.4.0 + Tika 3.1.0，Java 21 / Spring Boot）的市面做法对照。目的是让每一处改动都能指到一个成熟实现或公开规范，而不是自定阈值。

**怎么读**：第二章先给结论（可直接照搬 / 需改造后采用 / 明确不适用），第三章按问题域给做法与参数，第四章把本文结论映射到本项目的具体缺陷，第五章是出处，第六章是未能一手核实的条目。每条结论都标注了出处与证据等级。

**证据等级**（全文统一）：

| 标记                | 含义                                         |
|---------------------|----------------------------------------------|
| 源码核验            | 在本地依赖或官方发布产物里直接读到的实现事实 |
| 官方文档            | 项目官方文档 / API reference / 规范原文      |
| 官方源码页          | 官方文档站托管的源码页或官方仓库文件         |
| 第三方解读 · 未核实 | 来自博客等二手来源，行号与版本未闭环         |

## 六、未验证与存疑项

1. **RAGFlow 的版本口径**：本文 RAGFlow 结论均已核到 `v0.27.2` tag 的源码文件与行号；其主干已改为 Go 重写（`v1.0.0-rc1`，主干不再有 `deepdoc/` 目录），主干与 0.x 线的能力等价性未验证，落地前需确认对标版本。另外其 `naive` 路径把多栏最终排序与 `col_id` 分组注释掉（多栏主要靠文本合并时的栏守卫），`table_context_size` / `image_context_size` 在通用分支也被注释。
2. **pdf.js 官方 API 文档页**：本轮只取到官方发布产物与镜像站，`pageIndex` 为 0 基属 API 观感，未见官方原句。
3. **Docling 坐标原点默认值**：官方文档只写明「页面坐标以 72 points per inch」，默认是左下还是左上**未核实**，接入前需实测一行 bbox。模型权重仓库的许可文件亦未取到，代码 MIT 已确认、权重需单独核对。
4. **跨页续表能力**：Docling 与 PP-StructureV3 文档未见说明，MinerU 侧只有间接证据，marker 的跨页合并依赖云端 LLM 增强。纯本地默认配置下的三方案续表能力**均未验证**。
5. **MinerU 与 PP-StructureV3 的阅读顺序算法**：官方只给能力描述与指标，算法细节未披露，**未验证**。
6. **文本层与 OCR 结果的逐 token 冲突裁决规则**：各方案都只到「页级或块级判定」，未见可引用的仲裁规则。
7. **Tesseract 置信度量纲**：0–100 由 API 示例与 hOCR 字段推断，未见官方文档明写。
8. **PaddleOCR 输出字段名**：官方 `output_schema` 页面抓取被截断，字段名未一手确认。
9. **ISO 32000 页码边界与旋转条款原文**：未取到规范原文引文，需以本地规范第 14.11.2 节与旋转条目核对。
10. **许可口径冲突**：marker / Surya 权重门槛在 README 与定价页分别为 500 万与 200 万美元；docx4j 官网 403，许可未核实。
11. **各家性能与准确率数字**：来自厂商自评、竞品版本滞后、硬件不同，只能作量级参考；选型前需用本项目 50–200 页真实语料（中文合同 / 报告 / 学术 PDF + 扫描件）做一次小规模 A/B。
12. **模型化方案对 Office 的页码语义**：Docling 支持 DOCX / PPTX / XLSX 输入并统一输出，但 Office 的页码语义可靠性需实测。
13. **RAGFlow 版面模型的许可链路**：其版面识别类命名为 `LayoutRecognizer4YOLOv10`，上游 YOLOv10 仓库为 AGPL-3.0；直接使用或再分发该 ONNX 权重、或派生自其训练代码时需评估网络服务条款，仅借鉴阈值与流程不触发。OCR 部分派生自 PaddleOCR（上游 Apache-2.0）。
14. **产品许可的版本差异**：Open WebUI 现为 BSD-3 加品牌条款，`v0.6.5` 及更早为纯 BSD-3（切换点见其 `LICENSE_HISTORY`）；FastGPT 为 Apache-2.0 加附加条款（未授权多租户 SaaS、去 LOGO、外观专利声明）；AnythingLLM、LightRAG 为 MIT；PrivateGPT、Cognita 为 Apache-2.0；Verba 为 BSD-3-Clause；**Onyx 核心为 MIT Expat，但 `ee/` 目录（后端与前端均有）为企业许可**，照搬时只读非 `ee` 目录；**Khoj 为 AGPL-3.0**，其向量与行同库的设计只宜借鉴思路；**Dify 为修改版 Apache-2.0，禁止用其源码运营多租户环境且不得移除 LOGO**。
15. **状态码与产物**：RAGFlow 的 Document 状态码数值映射（0–4）未确认；其解析中间产物是否落库未验证；FastGPT 与 Open WebUI 在解析失败时是否保留产物未验证。
16. **未闭环的模型细节**：FastGPT 的 LiteParse WASM 内核是否保留坐标与阅读顺序未验证；RAGFlow 的行拼接模型 `updown_concat_xgb.model` 训练数据与准确率未验证；其 `_final_reading_order_merge` 在另一条解析路径（`parse_into_bboxes`）是否生效未核实。
17. **补空格阈值有两种公开表述**：源码级读取给出参数 `gap_ratio=0.25`（空隙超过 0.25 倍平均字宽补空格），而一份第三方源码解读给出的口径是「间距达到字符宽的一半」（0.5 倍）。二者相差一倍，落地前需以实际拉取的 tag 与参数默认值复核，不要在未确认前把它当标定值。
18. **摄取管线各家的未闭环项**：Onyx 的状态枚举成员数、面向用户的失败清单接口、切片参数配置入口未验证；Dify 是否对运行中任务做真终止、`retry_count` 是否有持久化字段、extractor 注册点未验证；Open WebUI 是否支持知识库级或文件级切分参数覆盖、删除文件是否级联删除向量未验证；PrivateGPT 的解析器与向量后端注册入口未验证（其老版 `ingest_service` 已不在 main）；LightRAG 的存储注册表名未验证；Khoj 的格式分派点未验证；Cognita 的路由层与 run 状态如何联动未验证；Verba 是否仍有入口点插件机制未验证。以上结论均取自 2026-10-03 的 main/master 快照，**行号会随提交漂移，引用时以「文件 + 函数名」为准**。
