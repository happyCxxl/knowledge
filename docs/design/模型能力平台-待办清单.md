# 模型能力平台 · 待办清单

本文件是模型能力平台待办的**唯一清单**：范围是 `knowledge-model` 出口与其消费方（解析 / 问答等），条目来自 [模型能力平台-方案设计.md](模型能力平台-方案设计.md)（当前 **v21**，已定决策 D1~D41）与 [实现-01-适配器骨架与真实调用.md](实现-01-适配器骨架与真实调用.md)，按「编号 → 范围 → 交付物 → 验收」列出，供逐条开工与状态跟踪。

## 一、编号与状态约定

编号两段式：`MODEL-xx`，与 `PDF-xx` / `OFF-xx` / `TASK-xx` / `PAGE-xx` / `DOC-xx` 并列，互不干扰；编号连续，不跳号。

| 状态 | 含义                                              |
|------|---------------------------------------------------|
| 已做 | 代码与文档已落地（附提交号）                      |
| 待做 | 口径已定，可直接开工                              |
| 待定 | 先要定口径才能开工（条目本身即待决策问题）        |
| 待核 | 先要核实外部事实（版本、Javadoc、库行为）才能开工 |

状态口径与 [解析环节待办清单](../stages/解析环节/05-待办清单.md) 一致。

## 二、与现有清单的关系

- 本清单是**跨环节的平台级**清单；解析环节清单的 `PDF-xx` / `OFF-xx` / `TASK-xx` / `PAGE-xx` / `DOC-xx` 各自独立回填。
- 本清单**不并入** `docs/stages/解析环节/05-待办清单.md`，两份清单互不改写对方条目。
- 登记一条交接：解析环节清单第三节 `PDF-04` 的那批实现（`CapabilitySidecarClient` 与三个 `Sidecar*Provider`）将被本清单的「能力访问层拆分归位」取代（条目 `MODEL-12`）。拆分口径按设计文档 **D33**：

| 原实现内容          | 拆分后归属                                                           |
|---------------------|----------------------------------------------------------------------|
| HTTP 访问与凭据     | 上移平台（配置键 `knowledge.model.vendors.*`）                       |
| 响应 → 领域结构映射 | 留在解析侧（`TableResult` / `LayoutResult` / `StructuredOcrResult`） |

## 五、使用方式

逐条开工：从「待做」取一条，先给问题说明与真实样例，确认后改代码 + 补单测；每条的交付物与验收按上表执行，完成后在本文件回填状态与提交号。门禁按片统一跑（`mvn -o verify`、静态检查、`node tools/check-comments.mjs`、`node tools/check-encoding.mjs`、前端 `pnpm lint`），中间每条只跑针对性单测。状态口径与解析环节清单一致。
