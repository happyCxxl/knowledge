# 环节整理与交接规范

> 定位：本规范沉淀自"文件输入"环节的整理优化实践，是后续所有环节（解析/组装/预处理/切片/向量化/构建索引）
> 做同类整理时的**统一操作手册**——按本规范逐环节执行一遍即可，无需逐次交代。
> 架构口径依据：`docs/implementations/知识库-整体架构落地设计.md`（A–J 决策，重点 A2/A7/A8/I）。

## 1. 总原则（五条）

1. **只动注释与结构，不改业务行为**——整理轮禁止改变任何可观察行为；每次改动前后行为一致（单测兜底）；
2. **详略与语义密度成正比**——公开接口完整 Javadoc；私有编排方法写"为什么+边界"；纯映射/直查方法一句职责即可；注释写"为什么"不写"是什么"；
3. **一切与代码核对，不信旧文档**——凡涉及命名、机制状态、数量、枚举清单的注释，逐条对照代码验证（本项目的注释漂移问题已多次踩坑，见 §4 反例清单）；
4. **收口有既定落点**——不发明新落点：VO 组装→Assembler、领域规则→rules、查询辅助→PipelineQuerySupport、Service 只编排、DTO 贫血；
5. **宁缺毋滥**——不加日期/版本等编造信息；不留"待定"字样在已实现代码的注释里；日志"每个故障有且仅有一条能定位"。

## 2. 标准工作流（每环节七步）

```
① 通读环节链路        controller → 触发 service → 消费/Runner（如适用）→ worker 算法 → 落库
② 产出问题清单        对照 §4/§5/§6/§7 检查项逐条打勾，列出"注释不规范/事实性错误/重复代码/日志缺失/分层违规"
③ 逐项确认           把清单呈给用户，确认修改范围（用户拍板后再动手）
④ 执行修改           先结构后注释；跨文件引用同步改（含测试、javadoc {@link} 链接）
⑤ 测试同步           装配变化→更新单测（纯映射无状态类用真实实例，见 §9）
⑥ 验证                mvn -Prun-tests test 全绿（见 §11）
⑦ 文档三件套          更新 step 档案（如需）→ 同步实现文档口径 → 新增/更新交接文档（见 §10）
```

## 3. 注释规范化细则

- **类注释**：职责边界（本类做什么/不做什么）+ 关键语义 + 依赖/调用方说明；`@author` 沿用既有值；
- **公开方法**：`@param` / `@return` / 边界语义（空值、失败、异常）；顺序流程用 `<ol>` 分点、并列要点用 `<ul>`；
- **错误/异常**：写清错误码与去向（抛业务异常 vs 正常返回失败结果，二者是不同契约）；
- **私有方法**：非显然知识才写（业务规则、并发边界、事务陷阱）；纯映射方法一句职责即可；
- **不写"为什么这么设置"**：注释只写"是什么"与当前状态（预留/待标定/一期不实现）；不写设计文档章节编号（9.8/11.3.3 类）、决策编号（R/D/T/A 类）、方案编号（B0X）、step 出处等设置依据；
- **枚举**：每个常量必须有注释；枚举类注释写明"字典 or 白名单"性质与落库形式（按实际落库形式如实写明：name()/value()/key()/中文展示值并存，以代码为准）；
- **DTO**：类注释写明"哪个实体的对外视图"；id 类字段注明 ToStringSerializer 防精度丢失的约定；
- **Mapper**：统一口径——表名 + 标准 BaseMapper + "业务查询一律经 XxxDbService 封装，不新增自定义 SQL"。

## 5. 分层收口细则（A8 规则 9，B01 已示范）

- **VO/响应组装** → `biz.service.support` 的 `XxxVoAssembler`（每环节一个，与 dto 环节包一一对应）；跨环节任务机制 VO 归 `TaskVoAssembler`；
- 四条硬规则：① Assembler 只做纯映射——不查库、不做业务判断，合成数据由 service 查好传入；② Service/Controller 不出现 `toXxx` 私有映射方法；③ 命名 `XxxVoAssembler` + 方法 `toXxxVO`；④ 查询辅助/步骤日志映射归 PipelineQuerySupport，纯实体→VO 映射归 Assembler；
- **领域规则** → `common.domain.rules`（A2：领域规则集中，biz/worker 可引用）；环节依赖/映射类规则独立成类（如 `StageFunnelRules`）；
- **响应组装单一出处**：同一响应的构造只允许出现一处（service 私有工厂或 Assembler 方法）；"taskId 求值策略（查 or null）"留在调用点显式表达；
- **不引入 MapStruct/converter 包**（A7）；DTO 不放静态工厂（贫血原则 + common 不能依赖 biz）。

## 6. 代码质量检查项

- IDEA duplicated code 告警 → 用**数据表达模式**（列表+循环）替代复制粘贴，行为不变、查询次数不变；
- 同构分支（如 N 个环节的装配）→ 环节列表驱动，新增环节只加一个元素；
- 私有方法搬家判据：被多处复用→共享助手；领域规则→rules；技术工具（第二个使用场景出现时）→工具类；**用例私有步骤留在服务里**（不追求"只保留接口实现"）。

## 7. 日志规范（稀疏但关键）

- **加**：状态跃迁点（校验通过/建档完成/复用）、失败兜底分支（warn + 上下文 id）、跨系统调用失败（带本端 id 关联远端错误）；
- **不加**：每环节内部重复同一信息的日志（上层已记 failReason 则下层不再记）、读接口查询日志、纯算法内循环日志；
- 格式沿用项目惯例：`===> ClassName method 事件, k=v`；warn 用于"需要人工关注但可自愈"。

## 8. 异常与错误码

- 框架层异常按语义翻译到错误码段（如 HttpMessageNotReadableException → 40001），不得落 40500 系统兜底；
- 错误码分段登记制（F 决策）：新增码先在 ErrorCode 枚举登记并同步实现文档错误码清单；
- 任务级错误码（PipelineTaskErrorCode）与 API 错误码分层，不进 HTTP 响应。

## 9. 测试同步规则

- 主类装配变化（新增/移除注入依赖）→ 同步更新单测构造；**纯映射无状态类（Assembler）用真实实例而非 mock**（mock 会让映射返回 null，断言失真）；
- 结构重构（循环化/方法迁移）→ 跑既有用例验证行为不变，不降级改断言；
- 单测风格：`@ExtendWith(MockitoExtension.class)` + `@Mock/@InjectMocks`（H 决策）。

## 10. 文档三件套（各自职责，不互相替代）

| 文档                                     | 定位                                     | 规则                                                                                                                                       |
|------------------------------------------|------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------|
| `docs/steps/step-XX-*.md`                | **决策档案**（历史记录）                 | 不改写历史，只追加；决策变化记录在"移交事项/封档记录"                                                                                      |
| `docs/implementations/*.md`              | 实现口径（类清单/流程/取舍/错误码/验证） | 随代码现状**同步重写**，过时口径必须修正                                                                                                   |
| `docs/handover/<NN><环节名>-环节交接.md` | 接手总览（逻辑/依赖/表关系/排查手册）    | 按统一模板（§10.1）；**正文不使用方案编号（B01 等），用环节名**；文件带两位编号前缀（如 `01文档输入-环节交接.md`）；文件链接保留历史文件名 |

### 10.1 交接文档模板骨架

```
# <环节名> —— 环节交接文档
1. 环节定位（全链路位置图 + 接手必读核心事实）
2. 接口清单（路径/入参/返回/要点）
3. 核心流程（分步时序表 + 边界语义）
4. 代码地图（分层表：层/类/职责）
5. 类依赖关系（模块依赖图 + 类级调用链 ASCII）
6. 数据模型与表依赖（ER 图 + 各表读写角色/约束/写入方 + 写入时序）
7. 关键机制（并发/幂等/收口规则/配置项）
8. 错误码与日志排查手册
9. 已知注意点（占位值/历史遗留/隐患，接手人避坑清单）
10. 相关文档链接
```

## 12. 项目级既定约定清单（后续环节直接沿用，不重议）

- HTTP 恒 200，错误语义走 `R.code`；鉴权为平台资源服务器共享能力；
- 手动逐环节与触发口径：解析环节上游只有原始文件——首次触发走执行链工作台文件入口，失败可重跑，成功/部分成功/进行中不重跑（成功后重跑由后端 40437 强制拦截）；下游环节（组装/预处理/切片/向量化）统一经上游产物节点「以此产物触发下游」启动，**可多次触发（多次触发即重跑，每次 = 新任务 + 新产物，旧产物保留）**；所有环节完成停终态、不自动串联下游；触发接口统一口径：RUNNING 重复触发一律 40431 拒绝、QUEUED 重复触发 = 补投唤醒不新建；
- 任务机制：DB 账本 + Redis 叫号（queueKey `knowledge:task:queue`，消息=taskId 字符串）；领取/终态回写均为条件更新；
- 主键雪花 ID（ASSIGN_ID），VO id 字段 ToStringSerializer；
- 平台五件套继承 BaseInfo；机器表仅 create_time；
- 枚举按环节分包 `common.enums.<环节>`；DTO 两层分包 `dto.<request|response>.<环节>`（存在跨环节功能包：knowledge/strategy/lineage/stagecontent/task）；
- 依赖钉版与排除项见 `docs/steps/step-02` 执行记录（升级前必读）；
- 产物存储走 ArtifactRepositoryPort（内容哈希寻址、不可变、可复用）；
- **环节输出统一继承 `common.domain.task.StageOutcome`**：suggestedStatus/errorCode/errorMsg/stepLogs/warnings 五个状态壳字段 + fail(errorCode, errorMsg) 快捷方法在基类一次声明，各环节 Outcome 只留业务载荷（parseResult/document/view/chunkSet/embeddingSet）；新环节照此继承，不重复声明状态壳；
- **子步骤日志构造统一走 `worker.pipeline.StepLogHelper`**（静态工具）：begin(stepName)/finish(step) 一对记真实耗时（duration=毫秒，五环节统一口径）；批量统计式步骤用 elapsedMillis(startedNanos) 累计各阶段耗时后写入 duration；禁止各管线私有 newStep/finishStep 副本；
- **源码批量改动一律经 read/write/edit 工具，禁止 pwsh 文本批量替换**：pwsh 的数组展平（`@(@(a,b))` → `@(a,b)`）会让 `$p[0]/$p[1]` 退化为字符串首字符，产生 i→m/r→e 类字符级损坏，且难以发现；仅允许 pwsh 做 Move-Item/New-Item 等无内容操作（2026-09 解析环节已踩坑，全程重写修复）。
